# VM API governance

VM API is an open community project. Contributions are welcome from everyone, regardless of employer or affiliation. Participants follow the [CNCF Code of Conduct](https://github.com/cncf/foundation/blob/main/code-of-conduct.md).

## Maintainers

Maintainers review contributions, guide technical direction, coordinate releases, and handle security reports. They keep the project welcoming and make decisions based on technical merit and user needs.

The initial maintainer is [Arunesh Pandey (@aruneshpa)](https://github.com/aruneshpa). Maintainer responsibilities and membership are recorded publicly in the repository.

## Decisions and contributions

Work is discussed through public GitHub issues and pull requests. Small changes can go directly to a PR; significant API or architectural changes should start with an issue so contributors can discuss the approach.

Maintainers seek agreement, consider feedback, and make the final decision when needed, explaining the reasoning in the issue or PR. There are no standing committees, mandatory voting procedures, or fixed discussion periods. Security reports and sensitive conduct matters are handled privately through the appropriate reporting channels.

Changes follow the repository's PR and CI requirements. While the project has a single maintainer, that maintainer may merge their own PRs using the configured bypass after checks pass. Any exception to passing checks must be explained in the PR. Independent review is encouraged whenever another qualified reviewer is available.

## Growing the maintainer team

Contributors who demonstrate sustained involvement, sound judgment, and constructive collaboration may volunteer or be nominated as maintainers through a public issue or PR. Existing maintainers consider community feedback, agree on appointments, and update the public roster and access permissions.

Maintainers may step down at any time and should help hand over their responsibilities. Membership changes are documented, with those affected given an opportunity to participate. If the project has no active maintainer, contributors should seek CNCF assistance with succession.

## Evolving this process

Anyone may propose improvements to this document through a PR. Maintainers will adapt governance as the community grows, adding process when it solves a demonstrated need.
